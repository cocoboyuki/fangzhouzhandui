# 2026 CRTC 参赛机器人设计与实现历程

**队伍名称：方舟战队**

## 六、视觉与感知

### 功能描述与开发历程

视觉模块主要用于识别方块类别和获取目标位置，为人工遥控或后续辅助控制提供信息。测距模块则用于补充目标距离信息。两者的作用不同，因此需要结合各自的测量范围和误差进行使用。

### 算法迭代过程

- **V1：HSV 颜色识别。**初期采用颜色阈值提取目标区域，再通过轮廓分析判断方块位置。这种方法实现简单、计算量较小，但在光照变化、背景颜色相近或物体出现反光时，容易出现误检。
- **V2：检测逻辑优化。**在颜色识别基础上，增加目标筛选、最近目标优先、目标切换判断和超时处理，减少目标在多个候选区域之间频繁切换的情况。该方法能够改善部分场景下的稳定性，但仍受颜色阈值和图像质量影响。
- **后续 YOLO 方案。**目前已使用电脑摄像头运行预训练模型进行初步验证。下一步计划采集比赛场地中不同距离、光照和遮挡条件下的方块图像，制作专用数据集，再根据检测效果决定是否进行模型训练和部署。

视觉检测得到的目标框中心可以用于计算目标相对于图像中心的左右偏差，但该偏差不能直接等同于实际距离。后续需要结合摄像头参数、目标尺寸或 ToF 测距结果，进一步确定目标位置。

### 测距与通信调整

早期测距方案采用单个 ToF 传感器。考虑到多个传感器可能存在 I2C 地址冲突，后续方案使用独立的测距模块，并根据实际硬件接口规划供电和通信方式。

由于部分 I2C 引脚与驱动板接口存在资源复用问题，需要重新安排测距模块的接线，避免不同设备同时占用同一接口。对于双 ToF 方案，应先确认传感器的地址设置、XSHUT 控制和初始化顺序，再进行多传感器联调。

当前计划通过串口将测距数据发送给 STM32，并在数据中加入帧头、距离、序号和校验信息，以便主控判断数据是否完整。通信频率暂按 50 Hz 设计，后续需要结合实际程序和测试日志确认。

### 后续改进方向

1. 记录不同光照和距离下的识别结果，分析误检与漏检原因。
2. 对视觉目标与 ToF 测量结果进行时间对应，避免将一个传感器测得的距离直接分配给所有检测目标。
3. 检查串口通信的帧完整性、超时情况和异常数据处理逻辑。
4. 在现有遥控功能稳定后，再逐步加入目标偏差提示和辅助对位功能，避免一次性引入过多自动控制环节。
